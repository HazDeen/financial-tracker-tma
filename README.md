# Smart Finance — веб-приложение

Русскоязычный учёт доходов и расходов: React 19 + TypeScript + Vite, FastAPI + SQLAlchemy. Работает в обычном браузере, включая телефон. Telegram для входа не нужен.

## Запуск

Нужны Python 3.11+ и Node.js 22.12+ (или 24+). Из корня проекта:

```sh
./start.sh
```

Открыть http://127.0.0.1:8000. Первый запуск устанавливает недостающие зависимости, собирает интерфейс и создаёт SQLite в `backend/web-finance.db`. Зарегистрируйте свой логин и пароль. Резервная копия этого файла сохраняет аккаунты, сессии и операции. Не удаляйте его при обновлении приложения.

Скрипт по умолчанию использует отдельную локальную SQLite, даже если в старом `backend/.env` указан PostgreSQL. Чтобы использовать PostgreSQL, явно передайте `DATABASE_URL` в окружении и предварительно выполните миграции. Существующие Telegram-данные сохраняются; новые веб-аккаунты используют отдельное пространство ID и не присваивают себе старые записи.

Разработка с обновлением интерфейса:

```sh
cd backend
DATABASE_URL=sqlite+aiosqlite:///./web-finance.db ../.venv/bin/python -m uvicorn main:app --reload
# В другом терминале из корня:
npm run dev --prefix frontend
```

Vite проксирует `/api` на локальный сервер. В production FastAPI отдаёт собранный `frontend/dist` и API с одного адреса. `VITE_API_URL` по умолчанию `/api/v1`.

## Аккаунты и хранение

- Регистрация: уникальный логин, 3–64 символа (`a-z`, цифры, `_`, `.`, `-`), без учёта регистра; пароль 8–128 символов.
- Пароли хешируются PBKDF2-HMAC-SHA256, 600 000 итераций и отдельная случайная соль. Сам пароль не хранится.
- Сессия на 30 дней в HttpOnly / SameSite=Lax cookie. На сервере хранится только SHA-256 токена. Выход отзывает текущую сессию.
- Все финансовые маршруты определяют аккаунт по сессии. Параметр `user_id` не даёт доступа к другому аккаунту. Непроверенный `/users/sync` отключён.
- Защита от запросов с чужих сайтов и ограничение регистрации/входа: 30 попыток в минуту с одного адреса на процесс.
- Записи лежат в базе, не в cookie или браузерном кэше. Общий компьютер: нажмите «Выйти».

## Учёт и выписки

Через «+» можно добавить ручной доход/расход, категорию, дату и сумму с копейками. В месячной сводке «Все» доступны изменение и удаление операции. Итоги и категории пересчитываются по сохранённым записям. Смены, долги и регулярные платежи сохранены из исходного проекта.

Импорт начинается с предпросмотра: количество операций, суммы доходов/расходов, первые 20 строк. Только кнопка «Импортировать» записывает данные. Ошибочная CSV-строка отменяет весь импорт. В результате показаны добавленные операции и дубли.

Поддерживаемые CSV:

- **Альфа-Банк / Альфа-Клик:** дата операции, приход, расход, валюта, описание, референс проводки.
- **Т-Банк / Тинькофф:** дата операции, статус, сумма/валюта платежа, категория, MCC, описание. Сумма платежа имеет приоритет над валютной суммой покупки; неуспешные операции пропускаются.
- **Сбер:** дата совершения операции, сумма в валюте счёта, описание, код авторизации.
- Универсальный CSV: `date;amount;description`, расходы со знаком минус. UTF-8/BOM и Windows-1251, разделители `;`, `,`, табуляция.

Учёт ведётся в RUB. Другие валюты без рублёвой суммы отклоняются, чтобы не складывать доллары с рублями. Формат XLS/XLSX нужно экспортировать в CSV.

PDF: только текстовый слой, распознаваемые карточные строки Альфа-Банка/Т-Банка с явным знаком суммы, Сбера с правилом «плюс = поступление» и первым денежным полем перед остатком, либо таблицы с явными колонками прихода/расхода. Скан, защищённый PDF и другие макеты требуют CSV. Предпросмотр нужно сверять с итогами исходной выписки. Универсальная поддержка всех версий PDF не заявляется.

Ограничения: 10 МБ, 100 страниц PDF, 10 000 операций в одном файле. Повторный импорт одного набора строк не создаёт дубли. Дата со временем, направление, сумма, полное описание и банковский референс участвуют в идентификации; одинаковые строки внутри файла различаются номером повторения. Если банк изменит время/описание между выгрузками или пересекающиеся файлы содержат разное число неразличимых повторов, автоматическое сопоставление не гарантируется. Старые импорты с прежним укороченным хешем автоматически не переиндексируются.

В интерфейсе можно скачать вымышленные тестовые CSV всех трёх банков (`frontend/public/examples`). Они созданы для проекта по изученным заголовкам, не являются личными банковскими документами.

Источники форматов и открытых примеров:

- [Открытые тестовые выписки Альфа-Банка и Сбера](https://github.com/gerasiov/ofxstatement-russian/tree/master/src/ofxstatement/plugins/tests/samples). Скачанные исходные CSV проверены парсером: Альфа — 3 операции (приход 33 123,56; расход 1 550), Сбер — 11 (приход 17 209,24; расход 9 870,41). Исходный GPL-код не включался в проект.
- [Заголовки CSV Тинькофф, опубликованные пользователем экспорта](https://github.com/moneymanagerex/moneymanagerex/issues/1859).
- [Альфа-Банк: доступные форматы выписки](https://alfabank.ru/help/t/corp/alfaforbusiness/vipiska/vipiska/v-kakom-formate-mozhno-skachat-vipisku/).
- [Т-Банк: получение выписки по счёту](https://www.tbank.ru/bank/help/debit-cards/junior/get-statement/account-statement/).

## Проверка

```sh
.venv/bin/python -m unittest discover -s backend/tests -v
npm run build --prefix frontend
```

Тесты используют временную SQLite, без доступа к рабочей базе и внешним AI-сервисам. Проверяют авторизацию, cookie/выход/срок сессии, изоляцию пользователей, валидацию денег, ручные операции, итоги, три CSV-формата, правила текстовых PDF и загрузку трёх вымышленных PDF, предпросмотр, атомарность и дубли.

## Размещение на сервере

Приложение готово к размещению; удалённый сервер этим изменением не обновляется. Для PostgreSQL:

```sh
cd backend
# DATABASE_URL=postgresql+asyncpg://... в окружении или backend/.env
../.venv/bin/alembic upgrade head
```

Новая миграция `b214a11c0180` создаёт отдельные таблицы аккаунтов и сессий, не меняя таблицу Telegram-пользователей. Она зависит от существующей локальной миграции `59aa15b75bdf_create_users_table_fix.py`: включите обе при доставке проекта. Удалённая БД не изменялась и миграции на ней не запускались.

Раздавайте сайт и `/api` через один HTTPS-домен, проксируя запросы на FastAPI. Установите `COOKIE_SECURE=true`. При использовании reverse proxy сохраняйте исходную схему/host и доверяйте forwarded-заголовкам только от вашего прокси. Для нескольких серверных процессов вынесите ограничение входа на reverse proxy/общий limiter. Настройте резервное копирование базы и актуальное окружение Python; существующая локальная `.venv` использует Python 3.9 и выводит предупреждения зависимостей.

Gemini — необязательная существующая функция: нужен `GEMINI_API_KEY`. Анализ запрашивается при открытии вкладки «Аналитик», а не при каждом входе; финансовая сводка при этом передаётся Gemini. Учёт расходов и выписки работают без ключа. Telegram-планировщик по умолчанию отключён.

Что осталось вне этой задачи: перенос старых Telegram-записей в веб-аккаунт, полноценные накопительные цели (в исходном проекте они были заглушкой). Существующее редактирование долгов/регулярных платежей через удаление и создание требует отдельной переработки; изменение обычных финансовых операций выполняется атомарным обновлением.


## Личный интерфейс 1.1

Главная, операции, расписание и профиль. Поддерживаются начальный остаток, зарплата и аванс по дням месяца, подписки с подтверждением факта оплаты и смена пароля с отзывом старых сессий. Интерфейс бело-синий, доходы зелёные, расходы красные. Смены и прежние дополнительные разделы убраны из интерфейса без удаления старых данных.

Локальный запуск: `./start.sh`, затем откройте http://127.0.0.1:8000. Для PostgreSQL примените миграции через `alembic upgrade head`. Сначала обновите backend, затем распространяйте APK. Актуальная версия и порядок обновления: [релиз 1.3.0](android/RELEASE-1.3.0.md).

Android-проект и сборка: [android/README.md](android/README.md).


### Восстановление пароля и произвольный период

При регистрации приложение выдаёт одноразовый резервный код. Сохраните его: на экране входа кнопка «Забыли пароль?» позволяет указать логин, этот код и новый пароль. После восстановления все прежние сеансы входа отзываются, выдаётся новый код. Для существующего аккаунта код можно создать в профиле, в разделе «Восстановление пароля», подтвердив текущий пароль. Новый код отменяет предыдущий. В базе хранится только SHA-256 кода; восстановление без заранее сохранённого кода не предусмотрено.

В сводке или истории нажмите на даты → «Диапазон», задайте начало и окончание, затем «Показать операции». Например, 23.09.2026–23.10.2026: доходы, расходы, категории и история включают оба дня целиком. Стрелки переключают соседние непересекающиеся интервалы той же длительности для сравнения.

Для PostgreSQL перед запуском новой версии выполните миграции `alembic upgrade head` из каталога `backend`. SQLite автоматически создаёт таблицу резервных кодов при запуске.


### Скачать Android-приложение с сайта

На экране входа и в профиле есть блок «Мои финансы на Android» с кнопкой скачивания APK, QR-кодом и инструкцией установки. Оба способа ведут на `https://finance.hazdeen.xyz/moi-finansy-1.3.0.apk`. QR-код находится в `frontend/public/android-download-qr.svg` и раздаётся с сайта без внешних генераторов. В Android-сборке этот блок скрыт.

Разместите APK в `frontend/public/`, чтобы веб-сборка сохраняла ссылку скачивания. Если заменяется уже готовый `frontend/dist/`, сохраните в нём APK либо скопируйте его повторно из `frontend/public/`. При смене версии обновите адрес в `AndroidDownload.tsx` и QR-код вместе.
